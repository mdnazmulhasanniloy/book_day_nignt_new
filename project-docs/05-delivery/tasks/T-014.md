## Steps

1. List every DELETE route that passes `validateReqBody(...)` (grep). For each, check in `api-usage-map.md` and the Flutter and Admin code whether the client actually sends the body the schema expects.
2. Make `validateReqBody` run for DELETE when a schema is explicitly passed (keep the current behaviour for GET/HEAD). Apply to `DELETE /media` first.
3. Because the live Flutter app may send DELETE without the body some routes now require, ship each affected route only after the check in step 1; list routes where the client does not send the body and leave them out (report in the PR).
4. S-01 (no auth on `/media`) is a separate open item and is not changed here.

## Result

- Commits: tests (failing first), code (`DELETE` added to `ALLOWED_WRITE_METHODS` in `system.utils.ts`), docs commit (hashes in the work queue progress log).
- Tests: `validateReqBody.delete.test.ts` (6): invalid type, missing body and unknown key return 422; the Flutter/Admin body shape passes unchanged; a DELETE route without a schema and a GET with a schema are unaffected. Before the fix 3 of 6 failed (200 instead of 422). After: server `npm test` 41 pass; `npm run test:db` 104 pass; `tsc --noEmit` clean. Lint and build not run (lint skipped in this repo). No migration, rehearsal not run.
- DELETE routes (all of them, grep of `*.routes.ts`): only `DELETE /media` passes `validateReqBody`; it is now enforced. Flutter `media_service.dart:69` sends `{"urls": [..]}` (and skips the call for an empty list) and Admin `media.api.ts:21` sends `{urls: [url]}`, so both satisfy the schema. The other DELETE routes (`/artists/:id/follow`, `/clubs/:clubId/follow`, `/event/:eventId/modules/:id`, `/hosts/:id`, `/event/:eventId/hosts/:hostId`, `/promo/:id`, `/waiting-list/:id`, `/wishlist/:type/:targetId`, `DELETE /profile`) have no body schema, so they are unaffected.
- Not verified: behaviour on a deployed build. S-01 (ownership of media deletes) is unchanged.
