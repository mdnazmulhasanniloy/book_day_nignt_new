## Steps

1. On `GET /explore/{id}?type=EVENT`: only for an existing, active event, `HINCRBY` a per-day Redis hash (`views:<yyyy-mm-dd>` field `<eventId>`); upsert `UserRecentEventView` for a logged-in user and keep the 20 newest. Stop incrementing `Event.viewCount` on every call: increment it from the same flush so it stays the lifetime counter.
2. Add a scheduler job `flushEventViews` every minute: read and clear the day hash atomically (rename-then-read), upsert `EventViewDaily (eventId, day)` with `views = views + n`. Use a deterministic jobId so two scheduler instances do not double flush (B-12).
3. Give each day hash a TTL of 3 days so keys cannot pile up if the flush job is not running (for example after a rollback to an older image).
4. If Redis is down, the view is dropped, not an error for the user.
