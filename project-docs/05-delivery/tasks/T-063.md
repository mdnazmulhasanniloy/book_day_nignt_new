## Steps

1. Create the migration folder `backend/prisma/migrations/<ts>_add_refund_requests/` and write the SQL by hand from `data-model.md` section 9, row 7. Update `schema.prisma` to match (`prisma migrate dev --create-only` is fine to scaffold; never `migrate reset`).
2. Create enums `RefundRequestStatus`, `RefundType`; table `RefundRequest` (see 8.2); `Refund.refundType NOT NULL DEFAULT 'FULL'`, `Refund.returnServiceFee NOT NULL DEFAULT false`.
3. Raw SQL partial unique index: at most one PENDING `RefundRequest` per `orderId`.
4. No UPDATE needed: existing refunds get the defaults (matches today's event-cancellation refunds).
5. Run the rehearsal script (T-002) from a clean restore. It must finish with exit code 0. Paste its summary (restore time, this migration's run time, backfill row counts, CHECK-violation counts) into the PR.
6. Update `data-model.md` (move this migration's text from section 8 to sections 2 to 6 only when the matching code ships) and `api-usage-map.md` if endpoints are affected.
