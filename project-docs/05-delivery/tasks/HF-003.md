## Steps

1. Verify before changing: find every writer and reader of the blacklist. Logout writes with `createRedisKey(REDIS_PREFIXES.blacklist, token)`; `auth.middlewares.ts:225,278` read the same helper; `auth.middlewares.ts:77` and `socket.middlewares.ts:48` read the literal `blacklist:jwt:<token>`. Record the list in the PR.
2. Replace the two literal reads with `createRedisKey(REDIS_PREFIXES.blacklist, token)`. Do not rename the prefix constant (it would orphan keys already in Redis).
3. Check the reset-page token (`recover.services.ts` blacklists it after use) is checked by the same helper, so a used reset token is refused.
4. Add a test with a fake Redis client: blacklist a token via the logout path, then call both middlewares and expect 401 / `Token blacklisted`.
5. Behaviour change to announce in the PR: tokens revoked before this fix start being refused on those two paths. That is the intended fix.
