## Steps

1. Implement `POST /v2/owner/events/{eventId}/change-notice` for a date or venue change: notify all ticket holders at once, keep unused tickets valid, offer a refund to those who decline within 7 days of the notice and before use, and show the exact deadline.
2. A last-minute change opens an immediate refund route (threshold is a setting; value pending the client). Refund the admission; the Technical Fee follows the partner-cancellation rule (rf_partner).

## Done when

- [ ] Test: a change creates one notice per holder with the deadline notice date plus 7 days.
- [ ] Test: a refund inside the window works; after the window or after use it returns 409.
- [ ] Test: a last-minute change (inside the threshold) allows an immediate refund.
- [ ] Test: tickets stay valid and the event time zone is used for the deadline.
- [ ] `npm run lint`, `npm run build` and `npm test` (in `backend/server/`, and `worker/` or `scheduler/` if touched) are green; DB-backed tests green with `npm run test:db`.
