## Steps

1. Create the migration folder `backend/prisma/migrations/<ts>_add_cities_filter_options/` and write the SQL by hand from `data-model.md` section 9, row 10. Update `schema.prisma` to match (`prisma migrate dev --create-only` is fine to scaffold; never `migrate reset`).
2. Create enum `FilterOptionKind`, tables `City` and `FilterOption` with the unique and normal indexes in `data-model.md` 8.2.
3. Backfill `FilterOption`: one row per distinct trimmed value of `unnest(Event.musicGenres)` (GENRE) and `unnest(Event.moodTags)` (MOOD), de-duplicated case-insensitively on `labelKey` (lowercase, trimmed), `sortOrder` alphabetical, `isActive = true`. Do NOT backfill `City` (no safe mapping from free-text locations).
4. The product-supplied starter lists and the city seed are loaded by T-032 when the client sends them.
5. Run the rehearsal script (T-002) from a clean restore. It must finish with exit code 0. Paste its summary (restore time, this migration's run time, backfill row counts, CHECK-violation counts) into the PR.
6. Update `data-model.md` (move this migration's text from section 8 to sections 2 to 6 only when the matching code ships) and `api-usage-map.md` if endpoints are affected.
