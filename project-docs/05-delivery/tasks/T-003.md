## Steps

1. Keep `tsx --test` and `node:test` (no new framework). Replace the explicit file list in the `test` script with a glob (`src/**/*.test.ts`) so new tests run automatically. Confirm the existing 3 test files still pass.
2. Add `src/testing/` with: (a) a `buildApp()` helper that mounts the Express app without listening (for `supertest`-style calls; add `supertest` as a dev dependency if the app is exported, else use `fetch` against an ephemeral port); (b) a Prisma test client pointed at `TEST_DATABASE_URL` that refuses to run unless the database name ends in `_test` or `_rehearsal`; (c) fixtures `createUser`, `createClub`, `createEvent`, `createTier`, `createOrder`; (d) an in-memory fake for the Redis client and the BullMQ queues (record `add()` calls, assert on them); (e) a Stripe fake (signature helper via `stripe.webhooks.generateTestHeaderString`).
3. DB tests run inside a transaction that is rolled back, or truncate touched tables in `afterEach` (pick the one that works with the ClubBooking EXCLUDE constraint and triggers; note the choice in the README below).
4. Add `npm run test:db` (needs `TEST_DATABASE_URL`) and keep `npm test` runnable without a database (DB tests are skipped with a clear message if the variable is missing).
5. Add one real example test per kind (pure function, route with fake Redis, DB-backed) as templates, and a 20-line `backend/server/src/testing/README.md`.
6. CI: add the `test` step to `backend/.github/workflows/ci.yaml` if it is not there; DB tests run in CI with a Postgres service container.

## Done when

- [ ] `npm test` passes locally without a database; `npm run test:db` passes against the rehearsal database restored in T-001.
- [ ] Pointing `TEST_DATABASE_URL` at a database whose name does not end in `_test` or `_rehearsal` makes the harness abort.
- [ ] A test can assert that a queue job was added with a given name and payload.
- [ ] CI runs both commands green on a pull request.
- [ ] Docs updated in the same PR as the code (`api-spec.yaml`, `data-model.md`, `api-usage-map.md`, `known-issues.md` as they apply); `x-status: planned` removed only for what actually shipped.
- [ ] `npm test` and `npm run build` in `backend/server/` are green.
