## Steps

1. `GET` with `status`, paging. `PATCH` with `{ decision: APPROVE|REJECT, approvedAmount?, returnServiceFee?, decisionNote }`.
2. APPROVE in one transaction: set the request APPROVED, create the `Refund` (`refundType` FULL when `approvedAmount` equals the full gross, else PARTIAL; `returnServiceFee`; `orderId` unique means a second refund is impossible), link `refundId`, then enqueue `processRefund`. `approvedAmount` defaults to the requested amount and cannot exceed the refundable gross.
3. REJECT requires `decisionNote`. Deciding an already decided request returns 409. Notify the owner with `REFUND_REQUEST_DECIDED`.
4. Do not touch inventory (Q9 default: no release). Do not change how event-cancellation refunds work.
