## Steps

1. For a known price, `POST /v2/table-requests/{id}/accept` (customer consent to the exact amount) creates a PaymentIntent with `capture_method=manual` on eligible methods; the request becomes PENDING_VENUE with the hold amount and `captureBefore` stored.
2. The venue's `/reject` cancels the authorization: the customer pays zero including fees; the release status is stored and returned (`holdStatus: RELEASED`).
3. Webhook `payment_intent.amount_capturable_updated` marks the authorization as held; duplicate events are idempotent.
4. A table is not confirmed in this task; only authorization and rejection.
