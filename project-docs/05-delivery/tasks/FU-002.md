## Why

`npm run lint` stops at start with "typescript-eslint does not support TS 7.0". The build scripts print that ESLint is skipped for the same reason. The root CI workflow has a lint job, but it is set to `continue-on-error: true` so that it reports the problem without failing the run.

## What to do

Found on `fix/merge-hotfix` (2026-11-24): `npm run lint` in `backend/server` fails at start with the message above. Versions: `typescript` ^7.0.2 (`backend/package.json` and `backend/server/package.json`), `typescript-eslint` and the two `@typescript-eslint` packages ^8.66.0. The failure is in the tooling, not in the merge.

- Either pin TypeScript to the newest version typescript-eslint supports, only for the lint tooling, or wait for a typescript-eslint release that supports TypeScript 7. Check the compiler (`tsc`) and tests still pass after any change.
- Fix what lint then reports, or agree a baseline.
- Remove `continue-on-error` from the lint job in `.github/workflows/ci.yaml`.

## Done when

- [ ] `npm run lint` runs in `backend/server` and passes.
- [ ] The CI lint job is blocking (no `continue-on-error`).
- [ ] `tsc` and all tests unchanged.
