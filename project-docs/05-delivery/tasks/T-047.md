## Steps

1. Create the migration folder `backend/prisma/migrations/<ts>_add_notification_types/` and write the SQL by hand from `data-model.md` section 9, row 2. Update `schema.prisma` to match (`prisma migrate dev --create-only` is fine to scaffold; never `migrate reset`).
2. `ALTER TYPE "NotificationType" ADD VALUE IF NOT EXISTS` for COLLABORATION_REQUESTED, COLLABORATION_RESPONDED, REFUND_REQUESTED, REFUND_REQUEST_DECIDED (four statements, the same way migrations 21 and 22 did). Keep this migration on its own: new enum values cannot be used in the transaction that adds them.
3. Update the TypeScript enum usage (`@prisma/client` regenerates) and any exhaustive switches over `NotificationType` (grep) so the new values do not break notification rendering.
4. Run the rehearsal script (T-002) from a clean restore. It must finish with exit code 0. Paste its summary (restore time, this migration's run time, backfill row counts, CHECK-violation counts) into the PR.
5. Update `data-model.md` (move this migration's text from section 8 to sections 2 to 6 only when the matching code ships) and `api-usage-map.md` if endpoints are affected.

## Done when

- [ ] Rehearsal script passes end to end with this migration included, on the restored dump.
- [ ] `npx prisma migrate diff` from the migrated rehearsal DB to `schema.prisma` shows no drift other than the known `btree_gist` item (BUG-B04).
- [ ] The old code (previous release image) still starts and passes `npm test` against the migrated DB (expand-only check).
- [ ] The four values exist in `pg_enum` after migrate (SQL check in the rehearsal).
- [ ] Notification list code does not throw on the new types (unit test with a fake notification of each type).
- [ ] Docs updated in the same PR as the code (`api-spec.yaml`, `data-model.md`, `api-usage-map.md`, `known-issues.md` as they apply); `x-status: planned` removed only for what actually shipped.
- [ ] `npm run lint`, `npm run build` and `npm test` (in `backend/server/`, and `worker/` or `scheduler/` if touched) are green; DB-backed tests green with `npm run test:db` once T-003 exists.
