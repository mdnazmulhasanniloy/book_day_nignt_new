## Steps

1. Reproduce first: `curl -X POST` the payment webhook and the Connect webhook with no `stripe-signature` header and with a wrong one. Expect 500 today (note the exact responses).
2. In `webhook.services.ts` (around the `constructEvent` call at line 37) and `connect.services.ts` (line 214): check that the header exists, wrap `constructEvent` in try/catch, and throw an error with `statusCode: 400` and a stable `errorType` (for example `INVALID_STRIPE_SIGNATURE`). Do not log the secret or the full payload.
3. Make sure the raw body is still what Stripe signed (do not change body-parser order). Valid signatures must behave exactly as before.
4. Add tests (use the harness from T-003 if it already exists; otherwise a plain `tsx --test` file that builds a request with `stripe.webhooks.generateTestHeaderString`).
5. Update the spec rows (`x-status`) and `known-issues.md` (remove B-16 when shipped).
