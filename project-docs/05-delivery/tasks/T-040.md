## Steps

1. POST creates the row idempotently (unique `(userId, eventId)`; a second POST returns 200 with the same state, no 409 and no counter change). DELETE removes it idempotently.
2. `interestedCount` is `COUNT(*)` on read, never a stored counter. No endpoint lists the users (Q6d default).
3. Only existing, non-canceled events can be marked; else 404.
