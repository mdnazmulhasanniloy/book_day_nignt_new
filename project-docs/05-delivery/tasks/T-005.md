## Steps

1. Create the migration folder `backend/prisma/migrations/<ts>_add_tier_on_purchase/` and write the SQL by hand from `data-model.md` section 9, row 5. Update `schema.prisma` to match (`prisma migrate dev --create-only` is fine to scaffold; never `migrate reset`).
2. Add `EventPurchase.ticketTierId` (FK to `EventTicketTier`, ON DELETE SET NULL), `EventPurchase.ticketTierName`, an index on `ticketTierId`, and the non-unique index `EventTicketTier(eventId, groupName, tierName)`.
3. Replace `prevent_event_purchase_snapshot_mutation` so it also compares the two new columns (copy the style of migration `20260923130000_add_order_purchase_idempotency`).
4. Do NOT touch `EventTicketTier` rows: `soldCount` stays exactly as it is. No backfill is possible for old purchases (they stay NULL).
5. Run the rehearsal script (T-002) from a clean restore. It must finish with exit code 0. Paste its summary (restore time, this migration's run time, backfill row counts, CHECK-violation counts) into the PR.
6. Update `data-model.md` (move this migration's text from section 8 to sections 2 to 6 only when the matching code ships) and `api-usage-map.md` if endpoints are affected.
