## Steps

1. Add `Event.maxTicketsPerOrder` (default 5) and `Event.maxTicketsPerCustomer` (default 10) with CHECKs (>= 1) in a small migration (part of migration 22 if T-089 has not shipped it; otherwise a new additive one).
2. In `POST /purchase/event` count the customer's PAID and PENDING_PAYMENT tickets for the event and reject over the limit with 422 `PURCHASE_LIMIT_EXCEEDED` (`limit`, `already`, `requested` in the body). A table booking is its own product and is not counted.
3. Flag a customer with 3 or more cancellations in 30 days (config constant) in a `CustomerFlag` row or a log line for admin review; no automatic block.
4. Owners can set both limits per event through `PUT /event`; omitted fields keep the default.
