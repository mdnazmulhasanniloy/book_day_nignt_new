## Steps

1. Add a helper `releaseEventTierStock(tx, orderId)`: for an order whose `EventPurchase` has `ticketTierId`, decrement that tier's `soldCount` by `personCount`, never below 0. It must be idempotent: guard with a conditional order status update (`updateMany ... where status = PENDING_PAYMENT` and act only when `count = 1`) so a repeated webhook cannot release twice.
2. Call it from the payment failed and payment canceled handlers in `webhook.services.ts`, inside the same transaction that moves the Order to `PAYMENT_FAILED`.
3. Orders without a tier link (all old orders, and no-tier purchases) release nothing. Do not try to guess a tier by price here; the estimate report is `reports/stock-leak.sql` and corrections are a manual client decision.
4. A late `payment_intent.succeeded` for an order already released must not leave the order PAID with its stock released: re-check capacity and, if the tier is full, flag the order for manual review (log with `traceId`, no automatic refund in this task).

## Result

- Commits: `be6b064` (tests), `dd7ea3d` (code), `be180b6` (DB test files run one at a time), docs commit follows.
- Code: new `webhook.helpers.ts` with `releaseEventTierStock({ tx, orderId })` and `reacquireEventTierStock({ tx, orderId })`. The failed/canceled branch of `webhook.services.ts` now calls the first inside the existing transaction instead of a blind `order.update`: a conditional `updateMany` (PENDING_PAYMENT to PAYMENT_FAILED) is the idempotency guard, and only when it matches does the tier lose `personCount` (`GREATEST(soldCount - n, 0)`, only for an EventPurchase with `ticketTierId`). PAID or already failed orders are not touched; orders without a tier link release nothing; no refund path was changed.
- Step 4 (late succeeded): when `payment_intent.succeeded` arrives for a FAILED PaymentTransaction whose order is PAYMENT_FAILED and has a tier link, the stock is taken again with a capacity check (`soldCount + n <= capacity`, atomic UPDATE) and the normal succeeded handling runs. If the tier is full nothing changes, nothing is queued (no PDF, transfer or push) and a `MANUAL_REVIEW` error is logged with the traceId, order id and payment intent id. No automatic refund.
