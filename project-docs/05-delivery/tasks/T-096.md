## Steps

1. Add `POST /v2/checkout/preview` (bearer optional): input is the basket (event tiers with quantities, table, extras, promo code, payment kind first online payment or balance). Output: line items, Technical Fee (percent and fixed shown as one or two lines according to display), Service Fee (never shown to the customer, only to the partner view), payable total now, balance due later, currency, refund-terms link, display hints.
2. It uses the same resolver and allocation code as checkout (one code path); `POST /purchase/*` recomputes and rejects a client total that differs when the new field `expectedTotal` is sent (409 `TOTAL_CHANGED`).
3. No stored state; rate limited; promo validation reuses T-019 limits.
