## What was found

- `media.routes.ts` had no auth on either method; anyone could upload up to 10 files per call or delete S3 objects by URL.
- Two client auth styles exist, so one existing middleware was not enough: Flutter sends `Authorization: Bearer` (`media_service.dart`); the Admin dashboard uses the `access_token` cookie plus `x-csrf-token` (`axios.configs.ts`, `media.api.ts`). The user bearer middleware only reads the header.
- All Flutter upload callers run after login (profile, add event, add club package, buy ticket). No signup or pre-login upload exists, so nothing legitimate is blocked.

## What changed

- `media/media.guard.ts` (new, dependency-free): picks the chain from the credentials present. Bearer header -> `checkUserAccessToken`, `checkUserExistence`, `checkAccountStatus` (any role). Else admin cookie -> `checkCsrfToken`, `checkAdminAccessToken`, `checkAdminExistence` (role ADMIN). Neither -> 401. A throwing step fails closed.
- `media/media.middlewares.ts`: wires the real chains as `requireMediaAuthMiddleware`.
- `media/media.routes.ts`: guard is first on both methods, so unauthenticated uploads never reach multer or disk.
- Response contract for success is unchanged. New error responses: 401 (stable `errorType`) and 403 (bad CSRF, admin session).

## Follow-up: ownership-based delete (2026-11-22)

Branch `feat/media-ownership` (from `release/hotfix`): migration `20261122120000_add_media_asset_ownership` (new `MediaAsset` table), `media.policy.ts`, `media.services.ts`, tests. Rules: ADMIN deletes any `attachments/` file; others only files they uploaded; unowned legacy files are ADMIN-only; strict URL parsing; all-or-nothing batches. Data-model section 6.1 documents the impact.

## Residual risks (still open after the follow-up)

- Resolved by the follow-up: non-admins can delete only files they uploaded. Remaining: files uploaded before the migration are ADMIN-only (no uploader known).
- `validateReqBody` does not run on DELETE (S-18): media now validates its own body; other DELETE routes are unchanged.
- Mobile token expiry on upload shows as a failed upload until Flutter B-07/B-08 land.
