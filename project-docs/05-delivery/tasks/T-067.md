## Steps

1. Handle `refund.created`, `refund.updated` (and `refund.failed` / `charge.refund.updated` if the account sends them; check which events the Stripe dashboard is configured for) to move `Refund.status` (PENDING, SUCCEEDED, FAILED).
2. Idempotent: duplicates are ignored (store the processed Stripe event id with the same mechanism the payment events use). Unknown refund id: log and return 200 (do not make Stripe retry).
3. A FAILED refund notifies the admin (log with `traceId`); no automatic retry here.
