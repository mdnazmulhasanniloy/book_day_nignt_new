## Steps

1. Create `backend/scripts/rehearse-migrations.sh` (bash, runs under Git Bash and Linux). Inputs: `DUMP_FILE` (default `backend/bookdianight.dump`), `REHEARSAL_DB` (default `bookdia_rehearsal`), `PGHOST/PGPORT/PGUSER/PGPASSWORD`. Refuse to run if the host is not `localhost`/`127.0.0.1`/a container name on an allow-list (safety against pointing at production).
2. Steps in the script, in order: (1) drop and recreate `REHEARSAL_DB` with `postgis` and `btree_gist`; (2) restore the dump and time it; (3) `prisma migrate deploy` for the migrations present in the repo, timing EACH migration (parse `_prisma_migrations.started_at/finished_at`); (4) run `05-delivery/reports/check-violations.sql`; (5) run `05-delivery/reports/stock-leak.sql`; (6) run the migration 4 review query from `data-model.md` section 9; (7) print a summary.
3. Write `05-delivery/reports/check-violations.sql` (SELECT only, each query returns a count and is labelled): `Order` rows that would break the NEW rules (`serviceChargeAmount >= 0`, `commissionAmount BETWEEN 0 AND grossAmount`, and the existing `sellerEarnings = grossAmount - commissionAmount`, `buyerTotal = grossAmount + serviceChargeAmount`); rows that would break the `PricingRule` CHECKs if the seed values were applied (`ServiceCharge.amount <= 0`, `ApplicationCharge` percent outside 0..100); `EventExtra`-style stock rules do not apply yet. Expected 0 rows for each. Add a query per later migration when that migration task is written.
4. The script exits non-zero if: restore fails, any migration fails, any CHECK-violation query returns rows, or `prisma migrate diff` shows drift beyond the known `btree_gist` item (BUG-B04). It prints but does NOT fix anything.
5. Output: a markdown summary to stdout and to `05-delivery/reports/rehearsal-<timestamp>.md` (ignored by git except the latest one referenced in the PR): restore time, per-migration time, backfill row counts (each migration task adds its own count query to a `backfill-counts.sql` the script runs after migrate), CHECK-violation counts, stock-leak summary, anything unexpected.
6. Document it in `backend/docs/database.md` (3 lines: how to run, what it checks, never on production) and mention it in `implementation-plan.md` M1.
