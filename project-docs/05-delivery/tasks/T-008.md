## Steps

1. Add `QUEUE_JOBS.EXPIRE_EVENT_TICKET_HOLD` and a payload type in `system.types.ts`. In `POST /purchase/event`, enqueue the job with a delay equal to the existing hold time (the same constant the module hold uses; do not hard-code 15).
2. Create `worker/.../expireEventTicketHold.job.ts` modelled on `expireEventModuleHold.job.ts`: load the order; if still `PENDING_PAYMENT`, mark it expired/failed using the same status the module job uses, call `releaseEventTierStock` (T-007) in one transaction, and cancel the Stripe PaymentIntent if the module job does for modules. If the order is already PAID or FAILED, do nothing.
3. Register the job in the worker's system queue and, if there is a job-name allow-list, in the server's.
4. Safety net: a scheduler sweep is NOT added here (keep scope small). Note in the PR that a lost delayed job leaks stock until a sweep exists, and that `reports/stock-leak.sql` can detect it.
