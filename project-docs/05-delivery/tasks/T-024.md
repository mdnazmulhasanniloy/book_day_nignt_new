## Steps

1. In `POST /purchase/event`, resolve the FEE (TICKET) and COMMISSION (TICKET) rules at order time, compute amounts with `computeAmount`, and store `appliedFeeRuleId` and `appliedCommissionRuleId` on the Order together with the existing snapshot columns. Money columns keep meaning exactly what they mean today.
2. Backward compatibility: with only the seeded GLOBAL rules, the totals must equal what the old code computes (same fee, same commission, same rounding). Add a regression test that runs the old formula and the new path on 20 sample orders.
3. If no rule resolves (should not happen after seeding) fall back to the legacy `ServiceCharge` / `ApplicationCharge` reads and log a warning with `traceId`.
4. Response shape for the buyer total is unchanged.
