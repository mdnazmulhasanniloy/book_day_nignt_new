# FU-001: Move the share page inline script to a file and add a Content-Security-Policy

| Field | Value |
|---|---|
| Stack | backend |
| Milestone | Follow-up (not scheduled) |
| CR / BUG IDs | S-23 (hardening after the fix) |
| Depends on | none |
| Size | at most half a day |
| Status | not started (follow-up, do not do before the owner schedules it) |
| Release checkpoint | with the next release that touches `explore` |

## Why

S-23 is fixed by escaping every value written into the share pages (`GET /explore/club/{id}`, `GET /explore/event/{id}`). A second layer is still missing: no `Content-Security-Policy` header. The page needs an **inline script** (the app deep-link redirect) and an inline style, so a strict policy cannot be set today without breaking it. The deep link is built with `jsStringLiteral`, which is safe, but a CSP would also stop any future mistake from running script.

## What to do

- Move the inline script out of the HTML template into a static file served by the server (or into a tiny route), reading the deep link from a `data-` attribute that is HTML-escaped. No inline script left.
- Move the inline style to a stylesheet, or allow it with a hash.
- Add the header for these routes only: `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src https: data:; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. Adjust `img-src` to the real thumbnail host (S3 public URL) if the page shows images.
- Keep the escaping from S-23 as it is (defence in depth).

## Done when

- [ ] The share page has no inline `<script>` and no inline event handler; the deep-link redirect still works in a real mobile browser and in the in-app browser, for iOS and Android.
- [ ] A test fetches the page and asserts the header is present and the body contains no inline script.
- [ ] The existing XSS tests in `explore.sharePreview.db.test.ts` still pass.
- [ ] Contract note in `api-spec.yaml` (the header is documented) and a changelog line.
- [ ] Checked on staging with a real phone before production.

## Notes

- Do not add a CSP header before the script is moved: it would break the page.
- Markup is still stored inside names and descriptions (the output is escaped). Write-time validation is a separate decision.
