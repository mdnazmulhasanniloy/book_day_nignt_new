## Steps

1. Add `GET /ticket-tier-presets`: a static list (name, `tierType` TICKET or PASS, sort order) kept in code, public or any logged-in role as the spec says. Preset names come from the tracker A2.5 to A2.7; custom names stay allowed.
2. Accept `tierType` on tier objects in `POST /event` and `PUT /event/{id}` (Zod schema; default TICKET). Return it on tier responses (additive).
3. Section vs tier rule (formal): a section is a parent tier (no price, no capacity of its own), a tier is a child or a top-level priced tier. Validate: a section cannot have `soldCount`, a child's parent must be a section of the same event. Existing events are not re-validated on read.
