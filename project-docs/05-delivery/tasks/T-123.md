## Steps

1. Write the contract first: add `SettlementArrangement`, `LedgerEntry` and `Transfer` to `data-model.md` (migration 16) and mark them planned.
2. Write migration 16 (forward-only): `SettlementArrangement` (event, mode, platform share, parties, status), `LedgerEntry` (order, payee, kind, amount, currency, state PENDING or CONFIRMED, expected transfer date), `Transfer` (ledger entries, Stripe transfer id, status, attempts, idempotency key). CHECK: amounts are non-negative and the shares of one arrangement total 100%.
3. Add `backend/prisma/tests/settlement_checks.sql` with CHECK-violation queries and run the rehearsal script on the restored dump.

## Done when

- [ ] SQL test: a share total of 99% or 101% is rejected by the CHECK.
- [ ] SQL test: a negative ledger amount is rejected.
- [ ] SQL test: two transfers with the same idempotency key are rejected (unique).
- [ ] Rehearsal script: RESULT PASS, no drift, the new tables are empty after migration.
- [ ] `npm run lint`, `npm run build` and `npm test` (in `backend/server/`, and `worker/` or `scheduler/` if touched) are green; DB-backed tests green with `npm run test:db`.
